# API v1

`POST /v1/courses/pdf` приема UTF-8 JSON и връща PDF байтове.
Заглавки: `Content-Type: application/json`, `Authorization: Bearer <token>`.

Успех: HTTP 200, `Content-Type: application/pdf`, `Cache-Control: no-store`.
`Content-Disposition: inline` съдържа ASCII fallback и UTF-8 име на файла.
PDF не е base64 и не е URL; WMS записва тялото на отговора като файл.

## Курс

| JSON ключ | Тип / задължителност | Значение |
|---|---|---|
| id | текст, задължителен, до 120 знака | ID; точно този текст се кодира в QR |
| name | текст, задължителен, до 240 | Име на курса |
| date | текст YYYY-MM-DD, задължителен | Реална календарна дата; PDF показва DD.MM.YYYY |
| created_by | текст, задължителен, до 240 | Създал |
| note | текст/null, незадължителен, до 10000 | Бележка; празна/липсваща не се показва |
| orders | масив, задължителен, 1–100 елемента | Нареждания в точния ред за печат |

## Елемент на orders

| JSON ключ | Тип / задължителност | Значение |
|---|---|---|
| client | текст, задължителен, до 240 | Клиент |
| client_id | текст, незадължителен, до 120 | Стабилно WMS ID на клиента за групиране; не се отпечатва |
| warehouse_order | текст, задължителен, до 80 | Номер на складово нареждане |
| invoice | текст, задължителен, до 80 | Номер на фактура |
| address | текст, задължителен, до 10000 | Адрес за доставка |
| product_count | цяло число 0–1000000, задължително | Брой позиции, не сбор от количествата |
| recipient | текст/null, незадължителен, до 240 | Лице получател |
| recipient_phone | текст/null, незадължителен, до 80 | Телефон на лицето получател |
| company_phone | текст/null, незадължителен, до 80 | Телефон по фирмена регистрация |

Празните контакти се показват като „не е посочен“. Идентификаторите и
телефоните не се преобразуват в числа. Задължителните текстове не могат да
са празни или само интервали. Непознати ключове се отхвърлят, за да се улавят
правописни грешки в интеграцията. Не се приема HTML за оформление: текстът
се отпечатва буквално. Кирилица и латиница се поддържат от включените шрифтове;
неподдържани знаци (например emoji) се връщат като 422, вместо да изчезват.

Ограничението на JSON тялото е 1 MiB. 100 нареждания и лимитите на текстовете
са технически ограничения на v1, не нови правила на WMS. Примерните шест
нареждания в три клиентски групи се побират на един лист; повече отделни клиенти
или дълги данни могат да изискват следващи страници. Много голямо нареждане има ясно продължение.

## Групиране и отметка „Доставен“ (версия 1.1.0)

Входът остава плосък масив `orders`; не изпращайте предварително групиран обект.
Генераторът обединява само съседни записи и никога не пренарежда маршрута.

- Ако и двата записа имат `client_id`, ID и `client` трябва да съвпадат точно.
  Различно изписано име създава отделна група, за да не се изгуби подаденото име.
- Ако и двата са без ID, трябва точно да съвпада `client`, включително регистър
  и интервали. За клиенти с еднакви имена подавайте различните им стабилни ID.
- Запис с ID и запис без ID са различни групи. Подавайте ID последователно за
  всички нареждания на клиента. `null` или празно ID е грешка; липсата е допустима.
- Ред A, A, B, A означава три групи; последното посещение на A не се премества.
  Броячът в PDF показва клиентски групи, а не уникални клиенти или адреси.

Общият фирмен телефон е в шапката. Ако телефоните в групата се различават,
всеки се показва към съответното нареждане, включително липсващ телефон.
Адресът, получателят, неговият телефон, документите и броят позиции винаги
остават по нареждане; не се сумират и не се заменят с обща стойност.

Една празна отметка 23 × 23 pt (около 8.1 mm) означава изпълнение на всички
нареждания в тази клиентска група. Тя е за химикалка, не е интерактивно поле
и не променя WMS статус. При продължение шапката се повтаря с „продължение“,
без второ квадратче. Ново посещение на същия клиент има собствена отметка.

## Грешки

```json
{"error":{"code":"validation_error","message":"Invalid course data.","details":[{"field":"/date","reason":"Invalid date; use YYYY-MM-DD."}]}}
```

| HTTP | code | Действие на WMS |
|---|---|---|
| 400 | invalid_json | Поправя JSON; дублирани ключове и NaN не се приемат |
| 401 | unauthorized | Проверява server-to-server токена |
| 413 | payload_too_large | Намалява заявката; лимит 1 MiB |
| 415 | unsupported_media_type | Изпраща application/json |
| 422 | validation_error | Показва/записва грешките по полета; не повтаря автоматично |
| 500 | generation_failed | Отбелязва неуспех и допуска контролиран повторен опит |

Неизвестен маршрут → 404 `not_found`; грешен HTTP метод → 405
`method_not_allowed`. Неуспешният отговор не трябва да се записва като PDF.
Всички application грешки са JSON; WSGI сървърът или reverse proxy могат да
отхвърлят по-големи/невалидни HTTP заявки преди приложението със собствен отговор.

`GET /healthz` е без токен и връща `{"ok":true,"version":"1.1.0"}`.
Документацията за инструменти е [openapi.json](openapi.json).
Източникът на схемата е [schema.json](../src/kursove_pdf/schema.json).
