# Внедряване в WMS

Генераторът е самостоятелна услуга. Не изисква достъп до ERP, WMS базата,
интернет или принтер по време на генериране. WMS backend-ът подава всички данни.

## Стъпки за програмистите

1. Стартирайте пакета до WMS backend-а по README и проверете `/healthz`.
2. Свържете WMS полетата с JSON договора от API.md. Запазете поредността на
   нарежданията; изпращайте текстови номера и date-only дата YYYY-MM-DD.
   Препоръчително подавайте стабилно `client_id` на всеки запис. Генераторът
   групира съседните записи автоматично по правилата в API.md.
3. След създаване на курс извикайте POST endpoint-а. При 200 запазете PDF-а
   към съответната версия на курса. Бутонът „Печат“ предоставя файла в браузъра.

При редакция на курса генерирайте нов PDF от актуалните данни. Свържете
заявката и резултата с версия/revision на курса, за да не замени бавен стар
отговор по-нова версия. Статусите, съхранението, retry опашката и правата за
достъп остават във WMS. Услугата не ги поддържа и не кешира файлове по course ID.

Грешка при генериране не трябва да показва стария PDF като актуален. WMS може
да маркира „PDF се подготвя“/„Неуспешно генериране“ и да предложи повторен опит.
Практична начална клиентска настройка: connect timeout 3 s, read timeout 30 s;
настройте спрямо измерените реални курсове и натоварването.

## Python backend пример (стандартна библиотека)

```python
import json
import urllib.request

body = json.dumps(course_data, ensure_ascii=False).encode("utf-8")
request = urllib.request.Request(
    generator_url + "/v1/courses/pdf",
    data=body,
    headers={"Content-Type": "application/json",
             "Authorization": "Bearer " + generator_token},
)
with urllib.request.urlopen(request, timeout=30) as response:
    if response.headers.get_content_type() != "application/pdf":
        raise RuntimeError("Unexpected generator response")
    pdf_bytes = response.read()
# Запишете pdf_bytes към revision-а на курса в хранилището на WMS.
# urllib.error.HTTPError съдържа неуспешния HTTP отговор и JSON грешката.
```

Или директно в Python, без HTTP:

```python
from kursove_pdf import generate_pdf, InputError
pdf_bytes = generate_pdf(course_data)
```

Пакетът няма зависимост от Flask request при директното извикване.
Токенът е нужен само при HTTP работа. Python функцията приема същата схема;
ограничението 1 MiB е на HTTP/CLI входа, а структурните лимити важат навсякъде.

## Мрежа и токен

Compose публикува само `127.0.0.1:8080`. Ако WMS е в друг контейнер, свържете
го към същата частна Docker мрежа и използвайте `http://generator:8080`.
Ако е на друга машина, настройте частен маршрут или HTTPS reverse proxy.
Не публикувайте токена във frontend JavaScript; пазете го в backend конфигурация.
Не добавяйте входните JSON тела и телефоните в proxy/application логовете.

Render работата е сериализирана в един процес заради споделеното състояние
на шрифтовете в ReportLab. За повече едновременни генерации пуснете отделни
процеси/контейнери зад вътрешен балансировчик. Няма споделена база или файлова
система за координация. Реалният капацитет трябва да се измери на целевата машина.

## Печат и QR

WMS отваря PDF-а локално; потребителят печата A4 при 100% размер. Генераторът
не изпраща команди към принтер. QR съдържа буквалното ID (UTF-8), не URL.
Свързването на скенера с визуализиране/търсене на курса се прави в WMS.
Проверете веднъж с реалния скенер и принтер преди production употреба.

Отметката „Доставен“ е за ръчно отбелязване върху хартия и не актуализира WMS.
След обновяване от 1.0.0 регенерирайте запазените PDF-и, които трябва да получат
новия дизайн; вече записаните файлове не се променят автоматично. Endpoint-ът
и старите валидни заявки остават съвместими.
